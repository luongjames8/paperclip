# 1.5: BELIEF DECOMPOSITION

## PURPOSE

Decompose the emerging topic into implied stakeholder roles to guide narrative search.

This step answers: "Who are the people in this story?"

---

## INPUT

| Input | Source |
|-------|--------|
| `topic` | Module input |
| `themes[]` | From 1_recon |
| `early_belief_signals` | From 1_recon (if any) |

---

## OUTPUT

```yaml
narrative_decomposition:
  topic: "[topic]"

  implied_roles:
    - role_id: NR_01
      role: "[role name]"
      specificity: "[specific enough to search - NOT generic]"
      search_vectors:
        - "[search query 1]"
        - "[search query 2]"
      discourse_locations:
        - "[source types where this role's discourse lives]"
      why_relevant: "[how this role connects to the belief]"
```

---

## PROCESS

### Step 1: Identify Implied Roles

For the topic/emerging belief, ask:

| Question | Role Type |
|----------|-----------|
| Who suffered the consequence? | VICTIM |
| Who made the decision that caused it? | ACTOR |
| Who discovered or revealed the truth? | DISCOVERER |
| Who tried to stop it? | RESISTOR |
| Who saw it from inside? | INSIDER |
| Who enforced accountability? | ENFORCER |

Not all roles exist for every topic. Surface only roles implied by the topic.

### Step 2: Make Roles Specific

Generic roles produce garbage searches. Specific roles produce narrative gold.

**Test:** Can you search this role directly? If too broad, narrow it.

### Step 3: Generate Search Vectors

For each role, generate 3-5 search vectors spanning different dimensions.

**Start with short-tail. Go long-tail only if short returns noise.**

### Step 4: Identify Discourse Locations

For each role, identify which source types (from the table below) are most likely to contain their discourse.

---

## SEARCH VECTOR DIMENSIONS

Generate vectors spanning these dimensions:

| Dimension | Pole A | Pole B |
|-----------|--------|--------|
| **Length** | Short-tail (1-2 words) | Long-tail (4+ words) |
| **Register** | Emotional/personal | Formal/institutional |
| **Perspective** | First-person | Third-person |
| **Specificity** | Generic terms | Named entities |
| **Temporal** | Evergreen | Time-bound (years, events) |

---

## SOURCE TYPES

| Category | Sources |
|----------|---------|
| **Social** | Reddit, Twitter/X, Facebook groups, forums |
| **Professional** | LinkedIn, Glassdoor, industry forums |
| **Media** | News sites, YouTube, podcasts, documentaries |
| **Institutional** | Court filings, congressional testimony, gov sites |
| **Academic** | Research papers, case studies, university archives |
| **Advocacy** | Nonprofit sites, victim advocacy groups, memorials |

---

## VALIDATION

Before output, check each role:

- [ ] Specificity: Could search this directly (not "people who...")
- [ ] Tied to belief: Role connects to the emerging topic/belief
- [ ] Searchable: Discourse locations identified
- [ ] Vector diversity: Spans multiple dimensions (short/long, emotional/formal, etc.)

---

## HARD CONSTRAINTS

- Minimum 2 roles, maximum 5
- Each role must have specificity (not generic)
- Each role must have 3-5 search_vectors
- Vectors must span different dimensions
- Roles must be tied to the topic/belief (not tangential)

---

## COMPLETION RULE

Done when:
- 2-5 roles identified
- Each role passes specificity test
- Search vectors generated spanning dimensions
- Discourse locations identified from source types

---

## GATE: DECOMPOSITION QUALITY

After this step, validate:

```
PASS: Each role specific enough to search directly
FAIL: Any role is generic ("victims", "critics", "people who...")
```

If FAIL → redo with more specific roles.
